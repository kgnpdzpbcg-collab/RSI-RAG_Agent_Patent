# 课题组已有专利的撰写逻辑分析

## 一、整体文件结构

该专利不是“技术交底书”格式，而是接近正式申请文件的完整结构，依次包括：

1. 专利申请信息确认表；
2. 说明书摘要；
3. 摘要附图；
4. 权利要求书；
5. 说明书；
   - 技术领域；
   - 背景技术；
   - 发明内容；
   - 附图说明；
   - 具体实施方式；
6. 说明书附图。

其中，摘要、独立权利要求、说明书“发明内容”和具体实施方式使用同一条 S1—S3 主流程，区别只在于公开程度逐层增加。

## 二、最核心的写作方法：同一技术主线逐层展开

### 1. 摘要：用最短篇幅写“主流程 + 技术效果”

摘要先用 S1—S3 概括技术方案：S1 数据获取和融合增强；S2 自适应开集网络训练；S3 开集故障诊断。随后对应三个技术层面说明效果：数据层缓解数据不平衡；模型层实现细粒度域对齐和原型特征学习；决策层实现类别自适应拒识。因此摘要本质上是“问题—三段手段—三段效果”的高度压缩版。

### 2. 权利要求1：只保护完成发明目的所必需的主骨架

权利要求1仍然使用 S1—S3，但不把所有实现细节塞进独立权利要求。独权保护完整机制链，从属权利要求再逐级锁定仿真模型、故障类别、融合策略、网络结构/损失和阈值计算等实现细节。

### 3. 从属权利要求：逐级锁定实现细节

其组织顺序是从数据来源、对象范围，到关键处理机制，再到网络/损失和具体决策公式。即：**独权保护“机制链”，从权保护“具体算法和参数化实现”。**

### 4. 背景技术：不写检索报告，而是构造“技术问题必然性”

背景技术的逻辑是：领域重要性 → 深度学习已有优势 → 数据不平衡 → 现有算法层/数据层方法为什么仍不够 → 引出物理仿真 → 再提出两个关键瓶颈 → “综上所述”收束成尚未解决的综合技术问题。该写法更接近正式说明书，不把查新过程写入正文。

### 5. 发明内容：先写一个“实际问题”，再完整复述主流程

“发明内容”先用一句话明确实际问题，然后再次写 S1—S3。随后采用“进一步地”逐层展开，与从属权利要求相互对应。最后按“数据层—模型层—决策层”总结组合技术效果，强调三个环节的有机结合。

### 6. 具体实施方式：把每个步骤落成可执行方案

具体实施方式先再复述一次 S1—S3，然后给出数据、算法、公式、网络、训练/测试流程、实验配置、对比方法和结果。也就是说，摘要、权利要求、发明内容和实施例不是四套不同方案，而是同一技术方案由概括到具体逐层展开。

## 三、对 RSI-RAG Agent 的直接启发

RSI-RAG Agent 适合照搬下面的组织方式：

> **背景中的 2 个核心瓶颈 → 发明内容中的 3 个主步骤 → 权利要求1保持同一主步骤 → 从属权利要求细化每一步 → 具体实施方式用航空电子电源模块知识查询场景把整条链跑通。**

不再采用上一版“交底书 + 查新表 + F1/F2”作为正式初稿正文。

## 四、RSI-RAG Agent 的结构映射

| 课题组已有专利 | RSI-RAG Agent 对应设计 |
|---|---|
| 数据层：仿测数据融合 | 任务执行层：Agentic RAG 规划、检索、证据验证 |
| 模型层：域适应+原型学习 | 经验层：检索轨迹 → REU → 正负经验对比/聚合 |
| 决策层：自适应阈值 | 策略层：Policy Overlay + 双门控 + 版本更新/回滚 |
| S1 数据融合 | S1 当前知识任务执行与轨迹形成 |
| S2 网络训练 | S2 已验证经验提炼与检索策略演化 |
| S3 开集判别 | S3 后续任务的策略匹配与自优化检索执行 |

本稿据此收敛为三个主步骤：**S1 知识任务执行与检索轨迹形成；S2 检索经验提炼与策略递归更新；S3 策略增强的后续知识服务。**
