# V0.5 Feature Chart：与主要近邻专利的逐特征比对

> 目的：以已经冻结的 V0.5 算法主链作为基准，判断是否存在单篇现有技术覆盖，以及多个现有技术之间是否存在直接、明确的组合启示。  
> 注意：本文件用于技术方案收敛和后续权利要求设计，不等同于正式法律意见。

---

# 1. V0.5 固定比对特征

将 V0.5 主链拆成八个相互依赖的技术特征：

- **F1 航空电子任务证据需求建模**：针对参数查询、BIT/BITE解释、故障分析、测试规程、维修处置等任务建立具有强制槽位和槽位依赖关系的 AERT。
- **F2 航空电子知识适用性门控**：候选知识必须经过 Equipment / Module / Revision / Operating Condition / Validity 等适用性校验后才能成为最终有效证据。
- **F3 多状态 Evidence State**：证据槽位不是简单有/无，而具有 EMPTY / PARTIAL / SATISFIED / CONFLICT 状态，且状态受适用性和依赖关系共同约束。
- **F4 状态导出的 Evidence Gap**：根据 Evidence State 生成 Missing / Uncertain / Conflict 三类 Gap，而非仅依据原始 Query 或一般缺失信息。
- **F5 Gap-conditioned 领域检索动作**：Gap 对应航空电子领域知识获取动作，例如 BIT/BITE 代码表、测试规程、维修手册、版本链、技术通告、测试页上下文等。
- **F6 Verified State Transition**：检索动作执行后，不仅统计新证据数量，而是验证 \(\Sigma_t \xrightarrow{A_t} \Sigma_{t+1}\) 中具体槽位是否从 EMPTY/PARTIAL/CONFLICT 转为 SATISFIED。
- **F7 跨任务状态迁移经验学习**：记录 Context + 前状态 + Gap + Action + 后状态 + Validation，并基于历史经验证状态迁移调整未来相似状态下的动作先验。
- **F8 Scope / Revision-aware 策略约束**：历史策略与设备族、模块、任务类型、工况、硬件/软件/文档版本绑定；版本不明或版本变化时触发重新验证、策略分裂、降级或回退。

固定主链：

\[
F1 \rightarrow F2 \rightarrow F3 \rightarrow F4 \rightarrow F5 \rightarrow F6 \rightarrow F7
\]

F8 贯穿 F2、F6、F7。

# 2. 重点近邻专利

## D1：CN121412426A《实验室安全检测方法、装置、设备及介质》

链接：<https://patents.google.com/patent/CN121412426A/zh>

- 从实验室图像和环境监测数据生成结构化综合查询；
- 需求分析日志提取核心信息要素；
- 信息审计日志识别有效信息和缺失信息；
- 缺失信息变成下一轮检索关键词；

- 循环检索直到缺失信息清零。

这是 V0.5 在“需求要素 → 缺失信息 → 下一轮检索”上的最强近邻。

## D2：CN121441642A / B《基于知识一致性验证的网络安全事件处置方法及系统》

- 检索结果必须经过最新版本验证；
- 检查与同类知识是否存在处置逻辑冲突；
- 检查是否符合安全约束；
- 未通过验证则阻断后续LLM处置流程并触发重新检索匹配。

这是 V0.5 在“知识适用性/版本/冲突 Gate”上的最强近邻。

## D3：CN121923941A《自动化渗透测试方法、系统、设备及介质》

链接：<https://patents.google.com/patent/CN121923941A/en>

关键公开：
- 静态知识库 + 单会话动态状态数据库；
- 根据当前状态对候选动作打分；
- 评分考虑检索相关性、前置条件匹配、Evidence Gain、风险和重复动作；
- 执行动作后，失败记录原因标签并降低类似动作，成功则提高相似动作统计值；
- 查询同时具有语义检索和平台/服务/版本等硬条件过滤。

这是 V0.5 在“当前状态 → 动作选择 → Evidence Gain → 成功/失败影响未来动作”上的最强近邻。

## D4：CN113401351A / B《Dynamic fault isolation for aircraft》

- 根据更新状态和历史维修数据再次生成不同的未完成 checklist。

这是 V0.5 在航空领域“状态更新 → 下一步任务变化 + 历史维护经验参与”的最强近邻。

## D5：CN119226439B《检索增强生成模型的控制方法、装置、设备及可读介质》

链接：<https://patents.google.com/patent/CN119226439B/zh>

关键公开：
- 历史交互影响动态关键词；
- 用户反馈调整关键词生成和文档特征提取策略；
- 强化学习状态可包含当前上下文、已检索文档和生成结果；
- 动作包括继续检索、结束检索和生成；
- 通过反馈持续优化 RAG。

这是 V0.5 在“历史经验改变未来RAG行为”上的通用近邻。

# 4. 单篇覆盖判断

## 4.1 D1 实验室安全

D1 覆盖“核心信息要素 → 有效/缺失信息 → 缺失信息再次检索”这一段，因此 V0.5 **不能把 Evidence Gap 驱动迭代检索本身作为独立创新核心**。

但 D1 没有公开：
- 航空电子 Effectivity Gate；
- 依赖关系约束下的多状态 Evidence State；
- 经验证 State Transition；
- 跨任务学习 \(\Sigma_t \rightarrow \Sigma_{t+1}\) 并调整未来动作。

结论：**未覆盖完整主链。**

## 4.2 D2 网络安全

D2 对版本最新性、逻辑冲突和安全约束进行强制验证，说明“版本/冲突门控”本身不能单独主张创造性。

但 D2 的验证对象是安全知识条目，并未形成：
- 按任务证据需求模板建立的槽位状态；
- 证据Gap→领域检索动作；
- 状态迁移经验递归学习。

结论：**未覆盖完整主链。**

## 4.3 D3 自动渗透测试

D3 是组合风险最高的文献之一。其已经具有：
- 当前会话状态；
- 候选动作空间；
- 前置条件；
- Evidence Gain；
- 成功/失败反馈；
- 相似动作统计值更新。

因此 V0.5 **不能只写成“根据当前state选择动作，并根据Evidence Gain/成败优化未来动作”**。

区别必须保持：
1. State 是由航空电子任务证据槽位及依赖关系定义的“Evidence State”，而非一般环境/攻击状态；
2. Action 是补齐某个工程证据状态的知识获取动作，而非攻击动作；
3. 验证对象是具体槽位的 EMPTY/PARTIAL/CONFLICT → SATISFIED 状态迁移；
4. Policy Scope 与航空电子设备、模块、工况和 revision 绑定。

结论：**未覆盖完整主链，但对 F6/F7 构成最明显创造性压力。**

## 4.4 D4 航空动态故障隔离

D4 在同一航空领域已经公开：
- fault code / scenario / current status / historical maintenance；
- 状态变化后动态改变后续 checklist；
- 历史维护经验参与任务序列生成。

因此 V0.5 **不能泛化声称“航空维修状态 + 历史经验 → 下一步动作”是新的。**

关键区别是：
- D4 优化的是实际 fault-isolation / maintenance checklist；
- V0.5 优化的是“知识证据获取动作”；
- V0.5 的中间技术对象是 AERT、适用性验证后的 KEO、Evidence State 和 Verified State Transition；
- V0.5 的输出是改变后续 RAG/Agent 的知识获取路径，而不是直接排列维修任务。

结论：**未覆盖完整主链，但要求我们明确“知识获取动作”和“维修执行动作”的边界。**

## 4.5 D5 通用反馈RAG

D5 已经说明：
- 历史数据和用户反馈可以持续调整 RAG；
- 继续检索/结束检索可以作为策略动作。

因此“RSI / self-improving RAG”名称和上位概念不能作为创造性依据。

但 D5 未公开 V0.5 的领域 Evidence State、Effectivity Gate、Gap-conditioned domain action 和 Verified State Transition。

结论：**未覆盖完整主链。**

# 5. 组合显而易见风险分析

最不利的组合并不是所有文献一起堆，而是以下三组：

## 组合 A：D1 + D2

- D1 给出：需求要素 → 缺失信息 → 再检索；
- D2 给出：版本/冲突/安全规则验证后才允许知识用于推理。

可能推导：
> “对缺失信息进行迭代检索，同时对检索知识做版本和冲突验证。”

这会压缩 V0.5 中 F2 + F4 的独立创造性空间。

但仍未自然导出：
- AERT 证据依赖；
- 四状态 Evidence State；
- 经验证状态迁移；
- 状态迁移经验跨任务学习。

## 组合 B：D1 + D3

- D1 给出 missing information driven retrieval；
- D3 给出 current state → candidate action → Evidence Gain / success-failure → future action statistics。

这是**最危险的组合**。

审查员可能认为：
> 把 D3 的自适应动作选择引入 D1 的缺失信息循环，可得到“缺失信息驱动动作并根据反馈优化动作”。

因此 V0.5 的创造性不能停留在 Gap + Action Learning。

真正区别要写成：
> **航空电子证据依赖模板决定 Evidence State；知识只有通过 Effectivity Gate 才能改变 State；RSI 学习的是特定领域证据槽位的经验证状态迁移，而不是一般 Evidence Gain。**

## 组合 C：D4 + D2 / D3

- D4 给出航空 fault scenario/current status/history → 动态后续任务；
- D2 可补版本/冲突验证；
- D3 可补状态→动作统计优化。

这组对“航空领域 + 状态 + 历史经验 + 动态动作”构成压力。

但跨越点仍然是：
> 从“维护执行状态 / 攻击环境状态”转变为“由航空电子工程证据依赖构造的知识证据状态”，并且把状态迁移直接用于 RAG 知识获取策略。

目前未发现上述文献提供明确技术启示要求以这种方式构造中间 Evidence State。

# 6. 当前结论

## 6.1 是否存在单篇覆盖？

**当前重点检索未发现单篇专利完整覆盖 F1–F8 主链。**

最接近的分别是：
- D1：Gap / missing information；
- D2：version / conflict gate；
- D3：state-action-evidence gain-feedback learning；
- D4：aviation status-history-dynamic next action；
- D5：cross-task feedback RAG optimization。

但这些文献的“state”“action”“evidence”技术对象不同。

## 6.2 是否可以停止重构？

按照 V0.5 已冻结的 Stop Rule：

- 尚未发现单篇完整覆盖；
- 最危险组合 D1 + D3 确实能得到“Gap-driven adaptive action”，但尚不能直接得到“航空电子证据依赖状态 + Effectivity Gate + Verified Evidence State Transition + Revision-scoped cross-task policy”完整链条。

因此当前判断：

> **暂不触发核心重构。**

后续重点从“继续发明更多模块”转为：
1. 把 F1–F8 的耦合关系写清；
2. Claim 1 不要把已有的 Gap、version gate、Evidence Gain 各自当成发明点，而要保护它们围绕航空电子 Evidence State Transition 的协同关系；
3. 从属权利要求分别锁定 AERT 任务模板、Effectivity Gate、四状态状态机、领域动作空间和 revision-aware policy。

# 7. 对正式权利要求的直接启示

Claim 1 的主骨架不应写成：

> “识别缺失证据，根据缺失证据继续检索，并根据历史经验优化检索策略。”

该写法极易被 D1 + D3 覆盖或组合。

Claim 1 应保持：

> **任务证据依赖 → 航空电子 Effectivity 校验 → Evidence State 更新 → 由该状态导出 Gap → Gap约束领域知识获取动作 → 验证动作导致的 Evidence State Transition → 用历史经验证 State Transition 调整后续相似状态下的知识获取动作。**

即将“Evidence State Transition”作为中轴，而不是把“Gap”“Agent”“RSI”三个词并列堆叠。

# 8. 其他值得模仿的垂直领域写法

虽然不是最接近对比文献，但以下公开专利值得在 V0.5 成文时学习其“领域化写法”：

- **CN121833939B 金融文档检索**：将普通文档转成包含核心事实、不确定性、缺失信息、来源可信度的支持性证据笔记；适合参考 KEO 的正文写法。
- **CN121441642A/B 网络安全事件处置**：把版本、更新时间、来源、可信度、冲突验证直接写进方法主流程；适合参考 Effectivity Gate。
- **CN121923941A 自动化渗透测试**：将平台、服务、版本、漏洞、TTP、工具等领域对象直接写进 Action 和 State；适合参考如何让算法“换一个领域就不成立”。
- **CN113401351A/B 航空动态故障隔离**：直接使用 fault code、fault scenario、aircraft status、historical maintenance 和 checklist；适合参考航空领域如何把真实维修对象写入算法，而不是只在标题中出现。
- **CN121542436A 航空维修知识图谱**：公开航空维修文本中的生效日期、失效日期、修订版本等时间属性；可用于支持本方案对航空维修知识 Effectivity / Revision 的工程必要性，但该专利本身以知识图谱构建为主，与本方案技术主线不同。
